# 방 데이터의 출발점

`migrations/202611070001_rooms.sql`은 Supabase 프로젝트의 auth.users, auth.uid(), authenticated/anon 역할을 사용한다. 개인 키나 실제 사용자 행을 이 파일에 넣지 않는다.

- 생성: create_couple_room(first_day, zone). 한 계정에 한 활성 좌석.
- 초대: issue_couple_invite(target). 48시간 유효. 재발급하면 이전 토큰을 폐기한다. DB에는 해시만 보관한다.
- 수락: accept_couple_invite(raw_token). 방 행 잠금, 토큰 소비, 두 번째 좌석 추가가 한 트랜잭션이다. 성공한 멤버의 같은 요청은 같은 방을 반환한다.
- 종료: leave_couple_room(target). 확인 UI에서 호출한다. closed_at을 기록하고 두 좌석과 초대를 회수하며 상대만 읽을 수 있는 알림을 남긴다. 개인 삭제·종료 방 보존 기간 후 정리는 P2에서 연결한다.
- 스키마 노출: 기본 public만 API에 노출하고 duri_private는 노출 스키마에 추가하지 않는다. 내 계정의 개인 자료/계정 삭제 API, 파일 삭제 작업, 실제 로그인 UI 및 Realtime 채널 정책은 P2에서 구현·검증한다.
- 로컬 검증: 프로젝트 루트에서 `npm run test:db`. 테스트는 실제 PostgreSQL을 시작해 인증 ID 인터페이스만 테스트용으로 만든다. 클라우드 연결 테스트는 별도의 테스트 프로젝트에서 수행한다.
- P2에서 신뢰할 수 있는 백엔드만 확정 이벤트를 발행하고 비공개 채널을 사용한다. 클라이언트 입력과 DB의 최종 상태는 분리한다.
- 현재 SQL 초안은 만료와 이미 소진된 토큰을 같은 오류로 반환한다. P2에서 유효한 초대 링크를 제시한 사람에게 필요한 안내(만료·이미 사용·재로그인 복귀)를 설계하고 방의 개인 데이터가 응답에 포함되지 않는지 검사한다.
